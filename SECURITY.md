# Security Policy

## Supported Versions

We actively monitor and patch security vulnerabilities. Please upgrade to the latest release to ensure you have the most up-to-date cryptographic fixes.

| Version | Supported          |
| ------- | ------------------ |
| v3.3.x  | :white_check_mark: |
| < v3.3  | :x:                |

## Reporting a Vulnerability

**Please do not open a public GitHub issue for security-related bugs.** Doing so exposes the exploit to the public before a fix can be deployed.

To report a vulnerability safely, please use one of the following methods:

1. **GitHub Private Vulnerability Reporting (Preferred)**: Navigate to the **Security** tab of this repository, select **Vulnerabilities**, and click **Report a vulnerability**.
2. **Direct Contact**: Email the maintainer directly at `kkeerthivasan811@gmail.com` with full reproduction steps.

### What to Include in Your Report
* A detailed description of the flaw or structural logic gap.
* Steps to reproduce the issue (including any scripts or specialized payloads).
* The potential impact (e.g., key exposure, data corruption, command breakout).

### Our Response Commitment
* **Initial Acknowledgment**: Within 48 hours of receiving your report.
* **Status Updates**: Periodic code evaluation details until a resolution patch is safely deployed.
